# 平涂、描边、空气透视、远景树海

> 注册表：[registry.md §6](registry.md)
> 覆盖：`flat` 平涂 · `rim` 描边 · 空气透视（`setHaze`）· 远景树海
> 来源：`demo/village/sea.js` + `demo/engine.js`（秋日山村场景的实现）
> 参考图实测工具：`tools/measure-haze.mjs` · `tools/measure-road.mjs` · `tools/solve-road.mjs`

这一篇记录四个**从参考图实测中提炼出来**的机制。
它们的共同点：**参考图和"按常理画出来"的结果差很远**，必须量过才知道差在哪。

---

## 0. 为什么必须实测

秋日山村的参考图最初被理解成"一片秋色树林 + 一个村子"。
实测后发现**三处根本性误解**：

| 误解 | 实测结果 | 工具 |
|------|---------|------|
| 顶部是天空（留白） | 橙色占 86.4%，绿/蓝/紫 ≈ 0% → **整幅没有天空**，全是层叠树海 | `measure-haze.mjs` |
| 公路是斜穿画面的 | 屏幕斜率实测 **0.3918**，路在画布 70%~93% 高度 | `measure-road.mjs` |
| 远处=更小更暗 | 远处是**更淡更灰**（饱和度 .80 vs 近处 .93） | `measure-haze.mjs` |

**教训**：几何和配色都不能靠目测。参考图里"路是斜的"这句话，
对应的世界坐标可以算出斜率 -4.79（几乎是垂直）或 0.39（正确）——
两者看起来都像"斜着"，但画出来完全不同。

## 1. `flat` 平涂模式

### 1.1 问题

`sphere()` 的默认光照是球面法线 + Bayer 抖动，
画出来的树冠是**一串葡萄**（每颗球有明显的高光和暗部）。

但参考图的树冠（3× 放大实测）是**平涂的金黄色块**，
只有边缘一圈深色勾线，内部几乎没有明暗变化。

### 1.2 实现

```js
// demo/engine.js
if (mode === 'flat') { pix[i] = mixHaze(rgb(c[0], c[1], c[2]), hz); continue; }
```

**直接写基色，跳过色阶和抖动。**

### 1.3 何时用

| 场景 | 模式 |
|------|------|
| 参考图的树冠（剪纸感） | `flat` |
| 人物剪影 | `solid`（带色阶但无抖动） |
| 石头、树皮 | `rough`（带噪声的粗糙感） |
| **勾边线** | `rim`（见 §2） |

### 1.4 坑

- `flat` 走的是 `rampOf` **之外**的路径，所以传进来的必须是 `[r,g,b]` 数组
- 平涂之后画面会"平"——需要靠**勾边**和**颗粒**补回立体感（见 §2、§3）

## 2. `rim` 描边模式

### 2.1 问题：为什么不能"先画大深球再画小金球"

想让树冠有一圈深色勾边，直觉做法是：

```js
sphere(x, y, z, r * 1.05, DARK, 'rough');   // 先画大的深色
sphere(x, y, z, r, GOLD, 'rough');           // 再画小的金色
```

**这行不通。** 引擎的深度是伪深度：

```js
const d = p.d + r * nz;    // nz = 球面法线的 z 分量
```

半径更大的球，`r * nz` 在边缘处**更大** → 深度值更大 → 深度测试**永远赢**。
结果：深色大球把金色小球整个盖住，勾边吃掉半个树冠。

### 2.2 实现：只画环带

```js
// demo/engine.js
if (mode === 'rim') {
  const inner = rp * RIM_INNER;              // RIM_INNER = .82
  if (dx * dx + dy * dy < inner * inner) continue;   // 内圈不画
  pix[i] = mixHaze(rgb(c[0], c[1], c[2]), hz);
  continue;
}
```

`rim` 模式在球内画，但**只画外圈那条环带**。
因为它画在主体**之后**，环带不受深度竞争影响。

### 2.3 描边粗细

| `RIM_INNER` | 环带宽（冠半径 12px 时） | 效果 |
|------------|------------------------|------|
| .70 | 1.8px | 粗描边，像剪纸 |
| **.82** | **1.1px** | **参考图的效果** |
| .92 | 0.5px | 几乎看不见 |

### 2.4 坑

- 勾边色要走 `flat`/`rim`（**不走 `rampOf`**）：
  `rampOf` 的 0 档是基色 × 0.4 再偏紫，会把深棕勾边压成黑紫
- 勾边会被**后画的树**覆盖 → 断续是正常的，
  参考图也是"后面的树压住前面的树"的剪纸叠压关系

## 3. 空气透视

### 3.1 原理

**远处不是"更小"，是"更淡更灰"。**

参考图逐行实测：

| 画面高度 | 平均 RGB | 饱和度 |
|---------|---------|--------|
| 顶部 | 240,194,49 | .80 |
| 中段 | 166,128,69 | **.58**（最淡） |
| 底部 | 201,128,15 | **.93**（最浓） |

### 3.2 两层实现

**① 逐物体雾**（引擎级）—— 按物体的世界坐标算雾量：

```js
// demo/engine.js
let hazeColor = null, hazeNear = 0, hazeFar = 1, hazeMax = 0;

function setHaze(color, near, far, maxAmount) {
  hazeColor = color; hazeNear = near; hazeFar = far;
  hazeMax = maxAmount == null ? 1 : maxAmount;
}
function hazeAmount(x, y, z) {
  if (!hazeColor) return 0;
  const d = Math.hypot(x, y) * .5 + (z || 0);
  return clamp((d - hazeNear) / (hazeFar - hazeNear), 0, 1) * hazeMax;
}
function mixHaze(color, amount) {
  if (!hazeColor || amount <= 0) return color;
  return rgb(lerp(color & 255, hazeColor & 255, amount), ...);
}
```

`sphere()` 在开头算一次 `hz`，整球用同一个雾量（逐像素算太贵）。

**② 全画面纵向雾**（场景级）—— 按**屏幕高度**衰减：

```js
// demo/village/sea.js
function applySceneHaze() {
  for (let iy = 0; iy < H; iy++) {
    const v = 1 - iy / H;                       // 越靠上越远
    const amt = Math.pow(clamp(v * 1.35 - .12, 0, 1), 1.5) * .30;
    ...
  }
}
```

### 3.3 关键：雾色的饱和度

**雾色必须是饱和的橙黄，不是奶油白。**

参考图顶部 B 分量只有 49、饱和度 .80。用奶油色当雾
会把整幅画冲淡成灰白（实测饱和度掉到 .46，中段 B 分量到 110）。

```js
const HAZE = rgb(248, 196, 52);   // ✓ 饱和橙黄
// const HAZE = rgb(250, 238, 196);  // ✗ 奶油白 → 画面发灰
```

### 3.4 雾量上限

`applySceneHaze` 的雾量上限 **0.30**。
超过 0.30 就会把饱和度拉到 .70 以下，而参考图是 .80~.87。

### 3.5 坑

- `mixHaze` 必须作用在**最终颜色**上，不能作用在色阶上
- 雾色要避开任何偏绿/偏蓝/偏紫的颜色 —— 参考图绿蓝紫都是 0%

## 4. 远景树海

### 4.1 它解决什么

参考图**整幅没有天空**。如果只画"一个村子"，画面会有大片留白，
和参考图的气质完全不同。

远景树海的作用：**把画面上部填满层叠退远的树**。

### 4.2 等距投影的关键：远 = `x+y` 小

这是最容易搞错的一点：

```
sx = OX + (x - y) / R2 * S      ← 水平位置由 (x - y) 决定
sy = OY + ((x + y) / R2 * 0.5) * S   ← 垂直位置由 (x + y) 决定
```

**"远"（屏幕上方）= `x+y` 小**，不是 `y` 小。
用 `y` 当深度轴布点，整片树海会跑到画布外。

### 4.3 按屏幕坐标布点

```js
// demo/village/sea.js
const sx = -30 + (k + .5) / count * 360;      // 屏幕横坐标
const dxy = (sx - OX) * R2 / S;               // 反解 x - y
const sum = seaSumFor(rowY, 0);               // 反解 x + y
const x = (sum + dxy) / 2, y = (sum - dxy) / 2;
```

**先定屏幕位置，再反解世界坐标** —— 这样永远不会布到画布外。

### 4.4 排距要小于冠高

排与排之间会露出背景带。冠在屏幕上的高度：

```
冠高(px) ≈ 树高(世界) * COS * S = 6.2 * scale * 0.866 * 9 ≈ 48 * scale
```

所以**排距必须 < 48 × scale**，否则出现横向白带。

| 排距 | 结果 |
|------|------|
| 30px, scale=.5 | 冠高 24px < 30 → **露白带** |
| 24px, scale=.6 | 冠高 29px > 24 → 连贯 ✓ |

### 4.5 前后景分层

参考图里**树压在房子前面**（树冠直接盖住木屋一角）。
用深度缓冲自动分前后：

```
树的世界 x+y 更大 → 深度更大 → 盖住房子   （近树压房子 ✓）
树的世界 x+y 更小 → 深度更小 → 被房子盖住 （远树在房子后 ✓）
```

所以：
- **远景树海**先画（`drawTreeSea()`）→ 房子盖在它上面
- **近景树海**后画（`drawTreeSeaFore()`）→ 它盖住房子

### 4.6 树冠形状

参考图的树冠（3× 放大实测）是**扁平的剪纸团块**：

```js
const FLAT = .70;                    // 竖向压扁
const zc = h * .80;                  // 冠心高度
sphere(x, y, zc, cr * .60, gold, 'flat');        // 平涂核心
for (let i = 0; i < 12; i++) { ... }             // 12 个簇
for (let i = 0; i < 26; i++) { ... }             // 26 个表层小球
// 然后 rim 描边
```

三个关键：

| 要素 | 参数 | 不做会怎样 |
|------|------|-----------|
| 竖向压扁 | `FLAT = .70` | 读作"葡萄串" |
| 平涂 | `'flat'` 模式 | 读作"一堆球" |
| 勾边 | `'rim'` 模式 | 树冠糊成一片，没有剪纸感 |

### 4.7 避让规则

| 区域 | 规则 | 原因 |
|------|------|------|
| 路面 | 绝对不放树 | 车要开过去 |
| 房子带（离路 5~14）| 小一号冠幅的填充树 | 填空白但不遮房子 |
| 村子屏幕带（y 300~470）| 正常大小的树，贴在房子外侧 | 参考图是树与房子交错 |

### 4.8 坑

- **树基不必落在台地上**。参考图是竖幅远景，地面延伸出画布很常见。
  加了台地限制会把树全滤掉（台地半宽只有 13~22 个世界单位）。
- 树冠的**竖向压扁**要用 `FLAT` 乘 z 偏移，不是缩小球半径
- 树海排数多、每排几十棵 → 渲染要一次 bake，不要每帧重画

## 6. 移植清单

| 优先级 | 项 | 说明 |
|--------|----|------|
| 高 | `rim` 描边模式 | 引擎里加 6 行。任何"描边"需求都要它 |
| 高 | `flat` 平涂模式 | 引擎里加 2 行。剪纸/像素画风格必需 |
| 高 | 空气透视 | 引擎里加 20 行。**这是"远景感"的最大来源** |
| 中 | 参考图实测工具 | `tools/measure-haze.mjs` / `measure-road.mjs` / `solve-road.mjs` |
| 中 | 无头渲染 + 并排对比 | `tools/render.mjs` / `tools/compare.mjs` |
| 低 | 远景树海 | 场景级实现，`demo/village/sea.js` 可直接抄 |

**通用坑**

1. **别凭目测调几何**。写工具量出斜率、占比、饱和度，再改参数。
2. **深度缓冲是伪深度**，大球永远赢 —— 描边要用 `rim`，不能靠"先画大的"。
3. **雾色要饱和**。奶油色雾会把画面冲成灰白。
4. **`rampOf` 会二次压暗**。固定色（勾边、描线）要绕过它。
5. **等距投影里"远"=`x+y` 小**，不是 `y` 小。
